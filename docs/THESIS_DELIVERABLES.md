# Thesis deliverables — checklist + how-to-generate each

A complete inventory of every artefact you need for the thesis report, with the exact command that produces each. Tick them off as you go. Designed so you can hand the .md to your supervisor and say "here's what's done, here's what's pending."

Pair with [`docs/STATUS.md`](STATUS.md) (project state) and [`docs/RUNBOOK.md`](RUNBOOK.md) (operational recipes).

## D. Qualitative examples (XAI evidence)

For the **Discussion** section. Show concrete cases where the Tier-2 judge or memory or RAG made a notable call.

| # | Deliverable | How to generate |
|---|---|---|
| ☐ | **3 examples where Tier-2 overturned Tier-1 as False Positive** (LLM rescued a normal user the static model wrongly flagged) | Filter benchmark CSV: `agent_final_decision == "False Positive"` and `human_ground_truth == "NORMAL"`. Pick any 3 rows, copy text + `agent_explanation`. |
| ☐ | **2 examples where memory likely helped** | Filter CSV: `agent_final_decision != agent_final_decision_with_memory`. Pick 2 where memory changed verdict for the better. |
| ☐ | **2 examples where RAG retrieval grounded the verdict** | Filter CSV: `agent_final_decision != agent_final_decision_with_rag`. Pick 2 with meaningful precedent influence. |
| ☐ | **1 honest failure case** | Find a row where all three (Static, Agent, with-memory) disagree with Human. Document why. Examiners love honest failure analysis. |

## G. Methodology snippets (write into the thesis prose)

Sentences/paragraphs you can adapt verbatim:

| # | What to say | Source |
|---|---|---|
| ☐ | **Sample size justification** | "Evaluation set: ~298 records sampled stratified-randomly across env_domain from 100k+ ingested across YouTube, Twitch, and Reddit, then deduplicated on (text, author_name) and hand-labelled. Comparisons use McNemar's test on paired classifier outcomes (per Dietterich, 1998)." |
| ☐ | **Agentic discovery framing** | "Unlike a closed-taxonomy classifier, the Context Agent proposes env_domain in free text. A downstream normaliser maps proposals onto a 16-category seed taxonomy via exact/alias/fuzzy match. Proposals failing all three are accepted as-is and logged for human review, providing a measurable agentic-discovery signal: the LLM proposed N off-seed categories across M streams." |
| ☐ | **Memory framing** | "The Tier-2 judge prompt is enriched with three context blocks: (i) the author's last 10 messages across all streams, (ii) the last 5 messages in the same chat thread, and (iii) a one-line behavioural fingerprint (e.g., 'Last 20 msgs: 16 Normal / 3 Offensive / 1 Hate'). These address the implicit-bias blindness failure mode identified in the internship report §6.3." |
| ☐ | **RAG framing** | "Retrieval-Augmented Moderation: past labelled cases are embedded with sentence-transformers/all-MiniLM-L6-v2 (384-dim) and indexed in Qdrant under cosine similarity. At judge time, the top-k=5 semantically similar precedents are retrieved (similarity ≥ 0.55) and injected as prompt context. Leave-one-out cross-validation evaluates against the existing benchmark without new manual labelling. Citation: Lewis et al., 'Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks', NeurIPS 2020." |
| ☐ | **Multi-platform claim** | "Three Layer-1 adapters (YouTube live chat via pytchat, Twitch via anonymous IRC, Reddit comment streams via PRAW) emit a Universal Schema payload to Kafka. Tier-1 and Tier-2 are platform-agnostic; per-platform accuracy (§1.8) shows the system generalises without per-platform tuning." |
| ☐ | **Engineering anecdote — duplicates** | "Before adding the Kafka consumer group_id, processor restarts caused message reprocessing. I detected this in the manual labelling pass — same text + author appearing multiple times — and deduplicated the evaluation set on (text, author_name) keeping the first occurrence. The fix has since been applied to the consumer config; subsequent ingestion runs are idempotent." |

## When to start writing the thesis

Right after you have the notebook §7 cross-pipeline table populated. That's the keystone result; everything else in the report points at it. Aim for: end-of-this-week have §7 with real numbers. Then start writing the Results section first (easiest — describe what's on screen), then Methodology (what produced those numbers), then Discussion (what the numbers mean).

Architecture, Background, Conclusion last.
